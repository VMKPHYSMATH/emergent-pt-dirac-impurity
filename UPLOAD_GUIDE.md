The scientific files are prepared for branch `revision/stationary-drive-20261028`
in `VMKPHYSMATH/emergent-pt-dirac-impurity`. Review the draft pull request and
the numerical scope before merging. Historical tags and files are retained.

Before journal submission:
1. Review the manuscript, Supplement and private response letters together.
2. Run `python reproduce.py --verify-stored`; inspect any rerun changes.
3. Choose the final release version. Reserve the new-version Zenodo DOI in
   the existing record before freezing the final bytes, where the deposit
   workflow permits; a reserved DOI is not yet a published deposit.
4. Enter the chosen release URL and reserved DOI in the data statement,
   update the letters' archive sentence appropriately, rebuild the PDFs and
   refresh hashes. Review and merge the final commit, then tag those bytes.
5. Upload and publish the matching files on GitHub/Zenodo; verify the resolved
   release and DOI. If automatic GitHub-to-Zenodo archiving is used, reconcile
   its assigned DOI and the archived files before claiming they match.
6. Upload the scientific PDFs and sources plus the private editorial letters.

Do not reuse the v2.1.0 fixed DOI for changed bytes. Changes after a deposit
require the archive's proper new-version workflow; do not silently describe
modified local files as the already-deposited snapshot.

This guide does not record a merge, release, Zenodo deposit or submission.
The metadata JSON is a draft, not evidence that a deposit exists.
